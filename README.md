# imapclient-yandex

Мониторинг Yandex Mail через IMAP. Проверяет `INBOX` нескольких ящиков, забирает
только новые письма и сохраняет их в локальную SQLite.

## Что делает

- Подключается к `imap.yandex.ru:993` по SSL, логинится по каждому аккаунту из
  `ACCOUNTS` (список в `.env`).
- Открывает `INBOX` и забирает **только то, что пришло после прошлого прогона**:
  запрашивает диапазон `UID <последний+1>:*`, а не весь ящик.
- Сохраняет `From`, `Subject`, `Date` и **текст письма** в `data/mail.db`.
  Вложения не скачиваются: тело — это первые 64 КБ сообщения (см. ниже).
- Логирует в `cron.log` с ротацией по дням.

## Как решается «не тянуть весь архив»

Прогресс хранится в таблице `state` — по две строки на аккаунт:
`uidvalidity:<user>` и `last_uid:<user>`.

| Ситуация | Что делает |
| --- | --- |
| Первый запуск аккаунта | Забирает `SINCE` вчера и сохраняет курсор `UIDNEXT-1`. Архив не импортируется. `SINCE` работает с точностью до календарной даты, так что это 24–48 ч |
| Следующие запуски | `UID <last_uid+1>:*` — размер ответа определяется новой почтой, а не размером ящика |
| `UIDVALIDITY` сменился | Ящик пересоздан: курсор сбрасывается, повторяется первичная загрузка |

Курсор пишется в одной транзакции с самими письмами, поэтому обрыв на середине
не приводит к пропуску: следующий запуск повторит тот же диапазон, а
дубликаты отсекает `UNIQUE(account, uid)`.

### Ограничения на стороне Yandex (проверено на живом ящике)

- `BODY[TEXT]` возвращает **всё письмо целиком, включая вложения** — 23 МБ на
  письмо, где текста 97 строк. Поэтому запрашивается префикс
  `BODY[TEXT]<0.65536>`; ответ приходит ключом `BODY[TEXT]<0>` независимо от
  запрошенного спека. Маленькие письма возвращаются целиком.
- `BODY[TEXT]` — это **body section** без верхнеуровневых заголовков, поэтому
  multipart-разбору приходится подставлять заголовок по границе из первых строк.
- `decode_header` квадратичен по длине: длинные заголовки обрезаются до 1 КБ,
  тела разбираются без него.

## Установка

Требуется [`uv`](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env
```

В `.env` — список аккаунтов **в одну строку** (dotenv не умеет многострочные
значения, pydantic-settings падает на старте с pretty-printed JSON). Используйте
**пароль приложения**, а не пароль от аккаунта:
<https://id.yandex.ru/security/app-passwords>

```ini
ACCOUNTS=[{"user":"box1@yandex.ru","password":"app-password-1"}]
```

## Запуск

Один проход (забрать новые письма и выйти):

```bash
uv run python main.py
```

Раз в 30 минут — через cron:

```cron
*/30 * * * * cd /opt/imapclient-yandex && flock -n /tmp/imapclient-yandex.lock /home/<user>/.local/bin/uv run python main.py
```

`flock` нужен, чтобы ручной запуск и крон не работали одновременно. Без него
два процесса читают один курсор, и часть писем может быть пропущена. Подробности
и безопасный ручной запуск по SSH — в
[deploy-imapclient-yandex.md](deploy-imapclient-yandex.md).

## Скрипты

| Команда | Что делает |
| --- | --- |
| `uv run python scripts/check_accounts.py` | Логин в каждый аккаунт из `.env`, без чтения писем. Код возврата `1`, если хоть один не прошёл |
| `uv run python scripts/check_cursor.py` | Логика курсора на фейковом клиенте: первый запуск, пустой прогон, новое письмо, смена `UIDVALIDITY` |
| `uv run python scripts/check_text.py` | Разбор MIME: QP, html-only, вложение, обрезанное тело, body section |
| `uv run python scripts/inspect_db.py` | Письма из `data/mail.db` |

Быстрые вопросы по базе, без дампа всех писем:

```bash
sqlite3 data/mail.db "SELECT account, count(*), max(uid) FROM emails GROUP BY account"
sqlite3 data/mail.db "SELECT datetime(received_at), subject FROM emails ORDER BY id DESC LIMIT 10"
sqlite3 data/mail.db "SELECT key, value FROM state"
```

## Структура

| Путь | Назначение |
| --- | --- |
| `main.py` | Подключение, курсор, выборка, сохранение, логирование |
| `scripts/` | Проверки и просмотр базы |
| `.env` / `.env.example` | Аккаунты (не коммитится) |
| `data/mail.db` | SQLite: письма + состояние курсоров (не коммитится) |
| `cron.log` | Лог приложения, ротация по дням, 7 копий (не коммитится) |

## Ограничения

Это спайк: без ретраев, без `IDLE`, без удаления старых писем, без
использования флагов `\Seen`. Письма, чьё тело длиннее 64 КБ, сохраняются
обрезанными. Ротация `cron.log` идёт по времени файловой системы — если
`TimedRotatingFileHandler` не сможет переименовать файл (например, `cron.log`
занят), он пропустит ротацию.
